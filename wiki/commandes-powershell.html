Administration et maintenance

Commandes PowerShell et accès au serveur

Déployer, ouvrir un tunnel SSH et consulter le serveur depuis Windows.

Sur Windows, ouvrir PowerShell et se placer dans le projet avec Set-Location 'C:\Users\A\Desktop\HTML\RPG GPS'. Depuis ce dossier, npm.cmd run deploy lance les tests, transfère et installe la version locale sur le serveur Linux. npm.cmd évite les problèmes éventuels de politique d’exécution de npm.ps1.

Accès au Dashboard : dans une première fenêtre PowerShell, saisir ssh -N -L 3001:127.0.0.1:3000 rpg-gps-server, laisser la fenêtre ouverte, puis ouvrir http://127.0.0.1:3001/dashboard/ dans le navigateur. Il est normal de ne plus pouvoir saisir de commandes : le tunnel reste actif. Ctrl + C le ferme.

Pour trouver la clé, ouvrir une deuxième fenêtre PowerShell, saisir ssh rpg-gps-server, puis sur Linux journalctl -u rpg-gps -n 30 --no-pager. Chercher la clé du Dashboard ; utiliser -n 200 si nécessaire. Si l’accès au journal est refusé, ajouter sudo. Le mot de passe Linux ne s’affiche pas pendant la saisie. exit revient à PowerShell sans fermer le tunnel de la première fenêtre.

Alternative depuis PowerShell : ssh rpg-gps-server 'journalctl -u rpg-gps -n 30 --no-pager' consulte le journal sans terminal Linux interactif. Sans RPG_GPS_DASHBOARD_TOKEN configuré, la clé change à chaque redémarrage du serveur.

Sur Linux, systemctl --no-pager --full status rpg-gps vérifie le service ; journalctl -u rpg-gps -f suit le journal ; free -h affiche la mémoire ; df -h / affiche le disque. sudo systemctl restart rpg-gps redémarre tout le service et interrompt les connexions : le document lié distingue aussi arrêt et démarrage.

Sur Windows, npm.cmd start lance un serveur local distinct du serveur Linux. npm.cmd test lance les tests. npm.cmd run wiki:build -- --note 'Description du changement' génère le wiki et son historique ; npm.cmd run wiki:export prépare son export sans publier. Ces commandes de maintenance ne changent aucune règle du jeu.
